# What I did today
- First was a reversing a string problem, basically every programmer has reversed a string at some point.
Haskell actually has a built in reverse function that does, that was a one line solution and was quite funny because it felt like 
cheating so I decided
to implement it from scratch.

    My first thought was a loop but I realized, I haven't actually seen any loops in Haskell yet, at least in 
the traditional way, so not that.
Next idea, recursion. 
I could solve the problem recursively by picking the each letter from the string and concatenating it to an empty string, so each recursion 
call would use the current string minus the head(the first letter).

    I spent several minutes on this, with a good chunk of that trying to figure out how to add a char to a string, which turned out to be extremely
easy. But eventually it worked. Yayy.


    However upon review, I found out my implementation had a time complexity of O(n<sup>2</sup>). This is because Haskell traverses the 
left string each time I append a new letter. With a bit of help, I was able to get it to O(n). The solution: the accumulator pattern. Instead 
of adding each new letter to the end of the new string, I could have a string(the accumulator) that 'walks with' the recursion, we take the head of the string
at that point, and prepend it to the accumulator.
